# 動能訊號回測

這份文件分兩部分：**事前登記**（跑之前寫好，之後不改）與**結果**（跑完才填）。
登記的內容若要修改，新增一節寫明改了什麼、為什麼，不覆蓋原文。

## 事前登記（2026-11-15，資料尚未下載）

### 要回答的問題

網站上的動能指標出現「放量的單邊 K 棒」之後，價格在接下來 1 小時是否往同方向延續，
而且延續的幅度扣掉交易成本後還有剩？加上 OI 與主動買賣比的確認條件，結果會不會更好？

### 訊號定義

門檻沿用網站圖例的分級邊界，是在看任何回測結果之前定的，不做調整。
所有指標都用訊號 K 棒（15 分鐘）收盤時已知的資料，算法與網站相同（`src/lib/metrics.ts`）。

| 訊號 | 條件 |
|---|---|
| 基本・做多 | 15m 漲跌 ≥ +0.5%，且 RVOL ≥ 2 |
| 基本・做空 | 15m 漲跌 ≤ −0.5%，且 RVOL ≥ 2 |
| 完整・做多 | 基本・做多，且買賣比 ≥ 1.25，且 OI 15 分鐘變化 ≥ +0.3% |
| 完整・做空 | 基本・做空，且買賣比 ≤ 0.8，且 OI 15 分鐘變化 ≥ +0.3% |

做空也要求 OI 增加：代表下跌是新空單進場推動的，不是多單平倉。

### 交易規則

- 進場：訊號 K 棒收盤後，下一根 K 棒的開盤價。
- 出場：進場後第 4 根 K 棒結束時（持有 1 小時），以再下一根的開盤價計。
- 同一合約、同一方向，持倉期間出現的新訊號不重複進場。
- 成本：來回手續費 0.10%（OKX 一般用戶吃單費率 0.05% × 2）。持倉期間若跨過資金費率結算，
  多單支付、空單收取當期費率。
- 不計滑價。訊號要到收盤後一兩分鐘資料才齊全，回測假設能以下一根開盤價成交，這對結果偏樂觀。

### 資料與樣本

只用 OKX（開發環境連不到幣安）。15 分鐘 K 棒，UTC 時間。

| 階段 | 期間 | 合約範圍 | 測哪些訊號 |
|---|---|---|---|
| 第一段 | 2026-11-01 至 2026-11-14（14 個完整日） | 2026-10-31 當日成交額前 50 名的 USDT 永續合約 | 基本與完整，多空共 4 組 |
| 第二段 | 2025-11-01 至 2026-10-31（12 個月） | 2025-10-31 當日成交額前 30 名的 USDT 永續合約 | 基本，多空共 2 組 |

- 合約範圍用期間開始**前一天**的成交額決定，避免用「現在很熱門的幣」回頭測而高估動能。
- OKX 的 15 分鐘 OI 與主動買賣量只保留約 15 天，所以完整訊號只能在第一段測。
- 第二段只用 K 線，用來看基本訊號在更長、涵蓋不同行情的期間是否穩定。
- 沒有調任何參數，所以不存在「樣本內調參」。兩段各自再切成前半與後半分別報告，作為穩定性檢查。

### 判定標準

主要指標：**持有 1 小時的每筆平均淨報酬**（扣手續費與資金費率後）。四組訊號各自判定。

- **有效**：筆數 ≥ 30，平均淨報酬 > 0，且以「進場日」為單位重抽樣（bootstrap，2000 次）的 95% 信賴區間下界 > 0，
  而且前半與後半的平均淨報酬同為正。
- **無統計意義**：筆數 < 30。只列數字，不下結論。
- **無效**：其餘情況。

另外報告但不作為判定依據：

- 毛報酬相對於「同一批合約、同一期間、同方向、任意時點進場持有 1 小時」的平均報酬的超額。
  下跌行情裡做空本來就賺，這個數字用來分辨訊號本身的貢獻與行情的貢獻。
- 持有 15 分鐘與 4 小時的結果，僅供參考。不會因為這兩個數字比較好看就改用它們下結論。
- 勝率、中位數、筆數最多的合約佔比。

### 預期與已知限制

- 預期方向：延續（平均毛報酬為正）。扣掉 0.10% 成本後是否仍為正，事前沒有把握。
- 預期失效的環境：盤整行情，放量 K 棒之後容易回吐。
- 第一段只有 14 個進場日，以日為單位重抽樣的檢定力很低，除非效果很強否則難以通過。
  第一段的結論只能當作初步觀察。
- 同一時間多檔合約一起觸發訊號時，這些交易高度相關，不是獨立樣本。以進場日重抽樣是為了處理這點。
- 一共檢定 6 組訊號，其中一兩組碰巧通過的機率不低，解讀時要打折。
- 第二段的合約範圍取自目前仍掛牌的合約，期間內下市的合約不在其中（倖存者偏誤）。

## 結果（2026-11-15 執行）

資料在事前登記推上 repo 之後才下載。門檻、交易規則與判定標準都照登記的內容，沒有調整。

### 結論

**六組訊號全部判定「無效」。** 照登記的規則，放量單邊 K 棒之後進場持有 1 小時，扣掉成本後平均是虧損的。

- 第二段（12 個月、約 6.4 萬筆交易）最有份量：做多與做空的平均淨報酬都是負的，95% 信賴區間整段在零以下，
  前半年與後半年方向一致。
- 連扣成本前的毛報酬都略為負值，也低於「任意時點進場」的平均。也就是說，這種 K 棒之後價格平均是小幅回吐，不是延續；
  0.10% 的來回手續費再把結果往下拉。
- 加上 OI 與買賣比的確認（第一段）沒有讓結果變好。「完整・做空」的平均淨報酬是正的，但信賴區間跨零、後半段轉負，
  判定仍是無效；它是六組裡唯一看起來好的一組，以碰巧來解釋並不勉強。
- 第一段只有 14 個進場日，而且期間整體下跌，本來就只能當初步觀察。它和第二段的方向一致。

這個結果否定的是「單根 15 分鐘放量 K 棒當進場訊號、固定持有 1 小時、以吃單成交」這一種做法，
不代表所有動能策略都無效。要測別的定義（例如更長的回看期間、跨幣種的相對強弱、掛單成交），
需要另外登記新的假設；而且這 12 個月的資料已經看過，不能再當成那些新假設的樣本外驗證。

### 與登記內容的出入

- **第二段的資金費率只算到最後 83 天**（2026-08-10 起）。OKX 只保留約三個月的資金費率歷史，更早的抓不到，
  該期間的交易沒有計入資金費率。影響很小：有資料的期間每次結算的費率絕對值平均約 0.007%，
  而持有 1 小時只有少數交易會跨過結算，換算每筆不到 0.002%，遠小於虧損幅度，不影響判定。
- 其餘照登記執行。

### 驗算

- 回測引擎的 RVOL 與網站用的函式逐點比對一致（`tests/backtest.test.ts`）。
- 第一段的四組訊號另外用一支不共用任何程式碼的 Python 腳本重算，筆數與平均毛報酬、平均淨報酬完全相同。
- 兩段資料的 K 棒數都等於理論上限，時間沒有缺口；第一段每根 K 棒都有 OI 與主動買賣量。

### 重現方式

```bash
node backtest/fetch-okx.mjs --from 2026-10-28 --to 2026-11-15 --universe 50@2026-10-31 --stats --out data/stage1
```

```bash
npm run backtest -- --data data/stage1 --from 2026-11-01 --to 2026-11-15 --signals base,full --title "第一段"
```

```bash
node backtest/fetch-okx.mjs --from 2025-10-28 --to 2026-11-01 --universe 30@2025-10-31 --out data/stage2
```

```bash
npm run backtest -- --data data/stage2 --from 2025-11-01 --to 2026-11-01 --signals base --title "第二段"
```

下載起始日比回測起始日早 3 天，是為了讓第一根 K 棒就有完整的 RVOL 基準。
第一段的 OI 與主動買賣量超過 OKX 的保留期限後就無法再從交易所重抓，只能用存檔（見下）。

## 每日存檔

`.github/workflows/archive-okx.yml` 每天 01:20 UTC 執行 `backtest/fetch-okx.mjs --archive`，
把保留期限內還沒存的每個完整日，以執行當時成交額前 80 名合約的 15 分鐘資料，存成每天一個檔案，放在 repo 的 `data` 分支。
檔案格式和回測讀的一樣，累積夠長之後可以直接拿來重跑第一段那種需要 OI 與買賣量的測試。
